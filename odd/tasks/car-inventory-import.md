# Inventory import: load a dealership's cars from a spreadsheet

Roadmap T3, redefined after checking how Mercado Libre actually works: their bulk
uploader only accepts a spreadsheet **they generate per category**, and vehicle
listings require a contracted package (15+ listings, ~1.16M ARS). So a hand-made
"CSV para MercadoLibre" cannot publish anything, and the honest highest-value task
is the other direction: getting 40 existing cars into the site without 40 forms.

A later ML-shaped CSV export stays possible; the API integration is a separate
project that needs the dealer's account and credentials.

## Specs

S1. An admin can upload a spreadsheet with many cars and see, **before anything is
written**, how many rows are valid and exactly which rows are not, with the
field and the reason.
S2. Nothing is created unless the admin confirms after seeing that report.
S3. Every row is validated server-side on both passes: the confirm pass re-parses
and re-validates the same file instead of trusting what the browser echoes.
S4. Brands and models are matched by name, case-insensitively, against the existing
catalogue; an unknown brand is a row error that names the value, never a silent
new brand.
S5. Enum columns accept either the stored value or the Spanish label the UI shows,
because a human fills the spreadsheet.
S6. Images are public URLs; each is downloaded and uploaded to Cloudinary. A photo
that fails does not fail the row: the car is created with the ones that worked
and the failure is reported.
S7. Only ADMIN can import, the file has a size and row cap, and a duplicate slug is
resolved the same way the single form does.
S8. The existing behaviour is untouched: the single-car form, the public catalogue
and the caches that serve it.

## Tasks

T1 — Pure CSV parser and row validator, with tests. S1, S3, S4, S5 | inline
T2 — `POST /api/admin/cars/import` with the dry-run and confirm passes. S1-S4, S7 | inline
T3 — Images: download and upload, per-row failures reported. S6 | inline
T4 — The admin screen: file picker, report table, confirm button. S1, S2 | delegated
T5 — Copy the template with the exact columns somewhere the admin can see it. S5 | inline

## Log

L1 (user, verbatim): "con el csv el administrador carga los autos en nuestra web y le
sirve para exportar a mercadolibre autos?" then, asked which to build first: "Import
primero".

L2 (research, dated): ML's mass upload is an XLSX **generated by ML per category**
(Publicaciones → Publicar → Masivamente), with fixed columns, `*` for required, titles
capped at 60 characters and images as **public URLs**. The API path uses `MLA1744`
with `MLA1744-MARC` and `MLA1744-MODL` marked required. Vehicles have **no free tier**:
"necesita tener contratado un paquete de publicación", contracted with their
commercial team; package prices from October 2025 start at 15 listings for
$1.162.500 (sin IVA, CABA & GBA). Attribute IDs must be read from
`GET /categories/MLA1744/attributes`, never hardcoded.

L3 (consequence for the roadmap): T3.1 as written ("inventory CSV export for
MercadoLibre") was oversold. A CSV cannot be uploaded to ML, so its value is a
spreadsheet for review and as a source to paste into ML's own template. Recorded so
the plan stops claiming otherwise.
